# Good Day 1.4.0 本机试用

本版为按用户要求进行的大改，暂不推送 GitHub，不发布云端下载包。沿用 E:\Apps\Good Day 和原数据目录，先保存、备份再就地升级。

## 功能与使用

左侧保留四个入口：今天、计划、目标、历史。

今天只按上午、下午、今晚分区，初次进入为空。点击每一栏添加提醒，日期默认当天，时间分别默认 09:00、15:00、20:00。名称和备注直接编辑；日期用日历选择，时间使用此前逐项滚动的小时、分钟滚轮。

计划与今天使用同一份提醒数据。先看今天、明天、后天，再按月展开后续日期；无提醒的月份以月份标题收起，展开后可按天添加，右上角加号也可以直接指定日期。修改日期会让同一条记录出现在对应日期，不创建副本。

重复支持：不重复、每小时、每天、工作日、周末、每周、每两周、每个月、每三个月、每六个月、每年。自定义支持每 N 小时／天／周／月／年（1～999），每周可选多个星期。工作日指周一至周五、周末指周六和周日，不按法定节假日调整。月末日期按实际天数调整，下个月恢复原日号；年度重复保留原月份和日号，兼容闰年。

重复事项在完成本次后生成下一次；若已经错过多轮，则安排下一次未来时间，避免一口气堆积很多记录。它不再沿用 1.3.7 中“未完成就每隔几分钟弹窗”的另一组设置。

提前提醒支持：无、5／15／30 分钟前、1／2 小时前、1／2 天前、1 周前、1 个月前。自定义支持分钟、小时、天、周、月（1～200）。月份使用日历月计算。提前通知与到点通知分别保存确认状态，前者确认后后者仍会提醒；新设置时已过去的提前时间会跳过，避免立即弹出很早之前的通知。到点时间已过去的未完成事项会显示为逾期，运行时补本次提醒。

日期跨天时，已完成记录保留完成日期；未完成事项仍以原日期显示在“已过期”区，不需要待安排页。完成后可在历史查找，今天也可显示或隐藏当日完成项。

## 旧数据

按用户确认，旧任务与旧计划先留在历史中，新版今天与计划从空白开始。原文件不删除、不改名、不批量转换，旧目标原样保留。旧任务的备注、子任务、目标关联、完成状态与完成时间都仍可查看；旧计划显示原截止日期和备注。历史保留搜索、完成／未完成切换、删除与结束旧重复规则。

新提醒单独存放在 Reminders/*.md，沿用原子保存、写入队列和 Vault 锁，纳入自动备份、手动备份、恢复和数据迁移。删除后进入垃圾桶，恢复默认暂停提醒。旧版事件和任务提醒在新工作流程中不弹窗，也不自动生成旧任务的新周期；旧文件仍保留在原目录及备份中。

此前存储检查加入的文件编号核对、恢复失败回退与中断恢复也保留在本版中。

## 参考

参考苹果提醒事项的今天、计划列表和日期分组思路，并采用用户指定的三个默认时间。苹果说明：[查看列表](https://support.apple.com/zh-cn/guide/reminders/remnd854fc47/mac)、[日期与重复设置](https://support.apple.com/zh-cn/guide/reminders/remnd4b206fb/mac)。

查阅了支持 Windows 的开源 [Remindr](https://github.com/MrDavidRios/remindr) 的提醒分组思路。实现使用本项目原有 Flutter 与 Markdown 存储，没有引入该项目的源代码。

## 试用检查

1. 初次打开今天，确认上午、下午、今晚三栏为空；目标内容仍在，旧内容可从历史搜索。
2. 在三个分区分别添加，检查默认日期和 09:00／15:00／20:00，填写备注、切换重复和提前提醒。
3. 将事项日期改到明天，在计划中查找同一条记录；展开无事项的月份，指定某天添加。
4. 设置自定义每周多个星期和自定义提前时间，保存、重新编辑、重启后核对。
5. 等待提前提醒并点击知道了，确认到点仍会提醒；完成本次重复事项后检查下一次日期及历史记录。
6. 检查跨日后逾期事项仍可见；删除并从垃圾桶恢复，确认恢复后暂停提醒。
7. 在设置备份并恢复，检查新旧记录都可恢复，界面能及时刷新。

全部操作先在本机审核，后续版本的 GitHub 同步仍需用户另行明确要求。

验证结果：155 项完整自动测试通过，静态分析无问题；340 与 400 宽度的实际界面预览、日期移动、跨日与托盘保存检查通过；Windows Release 构建和原生居中提醒测试通过。日期选择器的最终范围调整另经日期移动测试验证。
