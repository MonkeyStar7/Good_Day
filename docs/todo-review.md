# Good Day 1.3.3 内部审核

本次只在本机开发、提交、打包和安装，不推送 GitHub，不创建远程标签或发行版。GitHub 正式下载仍为 1.3.2。

## 界面

- “今日”改为“待办”。左侧保留待办、计划、目标、历史四个便签。
- 展开待办可直接编辑名称和一行备注，分别查看重复和提醒入口。打开“重复与提醒”只设置重复规则、提醒开关和提醒日期时间，不编辑名称、备注或任务安排日期。
- 重复保持仅一次、每天、工作日、每周、每月。设置界面中“仅一次”显示为“不重复”。计划页面保持现有功能。
- 收起待办后，备注直接显示在主名称下方，不添加勾选圈或子任务编号。
- 所属目标不再以收起时的标签显示；主名称使用目标颜色。展开后仍能选择所属目标。
- 历史只有“已完成”和“未完成”两种筛选，保留搜索；未完成包含以前未完成和已生成的未来记录。

## 提醒与旧数据

新提醒与待办保存在同一个 Markdown 文件中，稍后提醒和确认记录可在重启后恢复。确认提醒不会勾选完成待办。完成、删除待办后不再提醒；从垃圾桶恢复时提醒暂停，重新设置未来时间可启用。

重复待办的下一次继承提醒时刻及相对待办日期的天数。修改或关闭提醒也应用到同组已生成的未来未完成记录。跨日、退出后启动或唤醒仍补最近一次，过往重复记录留在历史中，不逐条弹出旧提醒。托盘后台和中央独立提醒卡片继续保留。

旧版 Events 文件不迁移、不删除，原有独立提醒继续运行。存在旧提醒时，设置中显示“已有独立提醒”，可查看、修改、暂停或删除；新待办无需在这里重复录入。

## 试用

1. 添加“刷三套试卷”，展开填写“整理错题”；收起后应直接看到备注。
2. 选择一个目标，收起后标题应显示该目标颜色，标题下方不再显示目标标签。
3. 打开重复或提醒入口：应只看到重复选择、提醒开关和提醒时间，没有任务名称、备注或任务安排日期。
4. 设置两分钟后的提醒，隐藏到托盘，确认仍在屏幕中央弹出；选择稍后提醒，重启后检查时间保留。确认提醒后待办仍未完成。
5. 创建重复待办并完成，检查下一次的提醒时刻。勾选完成或删除未到提醒时间的待办，确认不会再提醒。
6. 打开历史，分别查看已完成和未完成；搜索名称、备注与子任务。
7. 若旧版有独立提醒，在设置的“已有独立提醒”中确认记录和时间仍在。

内部隔离包使用单独 Vault 和配置；原安装目录的本机审核版继续使用原数据，更新前备份数据。
