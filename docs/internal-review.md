# Good Day 1.1.0 内部试用

这次仅在本地开发分支审核，不推送 GitHub，不创建远程标签或发行版，也不覆盖 `E:\Apps\Good Day` 中的正式版。

## 开始试用

完整解压 `Good-Day-1.1.0-internal-windows-x64.zip`，打开 `Good Day Internal` 文件夹，双击 `good_day.exe`。

内部版默认在程序文件夹上一级的 `review-data` 中建立独立 Vault 和配置。首次启动是空白列表，请添加测试任务；不会自动读取正式版任务。实际存放位置可在设置中查看。请不要在内部版中选择正式版正在使用的数据文件夹。

本机准备的试用目录含 3 个测试任务，用于检查昨日未完成、昨日完成和未来日期；ZIP 本身不带任务数据。内部窗口和托盘标记为“内部试用”，开机启动使用独立条目，建议试用时保持关闭。

## 本次改进

- 切页、打开设置、隐藏窗口和托盘退出前保存待处理编辑。保存失败会保留输入并阻止离开；缺少必填信息的新增计划会提示补齐或取消。
- 文件先写到同目录临时文件，完成写入后再替换原文件；写入失败保留原文件，写操作排队执行。
- 每天首次读取或修改前自动备份任务、计划、目标、每日记录、垃圾桶及外观设置，保留最近 7 份完整备份。设置 → 数据备份支持立即备份和恢复。
- 恢复前检查完整性和 SHA-256 校验值，并备份当前数据。恢复会将受管理的文件还原到所选时刻；可恢复“恢复前备份”找回刚才的数据。
- 无法解析的 Markdown 会保留并显示提示，避免内容从列表消失而没有解释。
- 常驻托盘时每 30 秒检查日期，重新显示、休眠唤醒和系统时间变化也会刷新。昨天未完成的任务顺延，昨天完成的任务不进入今天列表，未来任务不会被提前拉到今天。
- 再次启动同一程序会显示已有窗口。数据文件夹也有占用保护，避免新版不同路径的程序同时写同一个 Vault。

## 建议人工审核

1. 添加任务和子任务，修改标题后立即点“计划”，再返回今日，检查修改保留。
2. 修改目标的说明和颜色、计划的标题和截止日期，立即切页检查保留。
3. 编辑任务后直接关闭窗口，再从托盘显示；编辑后从托盘退出并重新启动，检查保留。
4. 新建计划但不选日期，切页时应提示补齐，输入不应消失。
5. 在设置 → 数据备份中立即备份；修改并新增任务；恢复之前的备份。再恢复“恢复前备份”，验证修改和新增内容能回来。
6. 从测试 Vault 中复制一个任务 Markdown，故意破坏复制文件的元数据。重新显示应用，检查无法读取提示及原文件仍在。
7. 连续双击程序，或隐藏到托盘后再次启动，应该只有一个内部版实例，并重新显示。
8. 让内部版跨午夜运行，或者休眠后第二天唤醒，检查日期、未完成任务和昨日完成项。自动化测试使用可控时间覆盖了这些逻辑，真实休眠仍建议人工观察。

## 边界和注意事项

- 本地备份与原数据在同一个 Vault 中，不能防范整个磁盘损坏。仍建议定期复制整个 Vault 到其他存储位置。
- 强制终止进程或突然断电可能丢失尚未开始保存的最后一小段输入；安全替换和备份保护已经保存的文件，不等同于实时按键日志。
- 完整 Vault 恢复由多次安全文件操作组成；中途异常时会提示失败，恢复前备份可用于找回原状态，不宣称整个文件夹具备一次性事务。
- 旧版 1.0.0 尚无数据文件夹占用保护，内部试用不要让新旧版指向同一 Vault。
- 测试及本机启动通过不代表所有 Windows 设备均已验证。正式发布前建议在无开发工具的 Windows 10/11 x64 设备上补做首次启动和更新测试。
