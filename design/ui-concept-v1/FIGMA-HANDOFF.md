# Good Day UI 设计交接 · V1

这是一套设计提案，供 Figma 重建和交互原型使用，尚未实现到应用。
使用内置 image_gen 生成 3 张视觉参考板。PNG 不是可编辑的 Figma 组件；文字、间距、图标和交互以本说明为准。

## 设计方向

安静的桌面便笺。保留可拖动的窄长窗口、直角、行内编辑、今日 / 计划 / 目标的产品结构。视觉层级主要依靠字体、间距、细线和少量强调色。内容区需要可读，透明感不能让桌面的文字穿透任务文字。

- 01-main-views.png：今日、计划、目标。
- 02-inline-editing.png：任务详情与子任务、计划日期编辑、目标编辑。
- 03-settings-trash.png：设置、垃圾桶、删除确认。

## 页面逐项方案

### 今日

标题下用小号“今日 · 计划 · 目标”作为直接切换入口，当前项加深。标题区域仍支持原来的循环切换；若保留箭头，应使用向右箭头表达“下一个”，不要把下拉箭头和循环行为混用。

日期和完成数量各占一端，不放鼓励标语或装饰图。列表保留序号、主完成圈、任务名；目标用小色点 + 名称。任务文字优先，标签过长可换到下一行。展开箭头只在悬停 / 键盘聚焦时强调。

备注折叠后不显示。子任务折叠后仍逐行以小字显示，并能独立勾选。已完成内容弱化但保持可读，避免同时变得过浅又加重删除线。

添加行始终位于已有任务下方，整行可点击。空列表保留“1 +”和 3 条淡分隔线，无插画、无空态大段文案。

### 计划

沿用今日的列表结构。每项显示名称、目标标签、截止日期、剩余天数和细时间条，主完成圈必须保留（第一张生图遗漏了计划完成圈，重建时补上）。

进度条表示剩余时间，不是完成进度：
remaining = clamp((deadline - now) / (deadline - createdAt), 0, 1) × 100%。
示例百分比仅用于视觉，实际必须由真实时间计算。创建计划必须填写截止日期。
未选日期时保留草稿并在日期字段下提示“请选择截止日期”，不得默默创建。
今天截止显示“今天截止”；逾期显示“已逾期 N 天”和空时间条；已完成显示完成状态，不继续以逾期样式强调。

日期选择器锚定在字段附近，空间不足时向上展开或在窗口内滚动，不能越出窄窗口。日历仅是选择日期的辅助浮层，计划本身始终行内编辑。

### 目标

目标是一种分类标签，不增加层级或统计面板。每行名称、单行描述和一条短颜色标记；描述长时折叠截断，展开可见完整内容。
点击行就地编辑名称、描述和颜色。颜色选中同时用勾和描边表达，不能只靠色差。
标签本身不做完成进度条，也不加入新截止日期功能。

### 设置

顺序为外观、桌面、数据。组间留白，组内分隔线，避免大边框套小边框。
字体选择就地展开单选项，并提供一行实时样例；主题色即时预览。
“开机启动”开关必须反映真实系统状态，操作中短暂禁用，失败显示说明并恢复实际状态。
“关闭窗口：隐藏到托盘”目前是固定行为，应当作为说明行，删去生图里的右箭头。
“存放位置”显示当前路径和更改入口；更改调用系统文件夹选择器。
“迁移后删除原数据”默认关闭。迁移错误明确显示原因；删除前仍要确认。
垃圾桶是一行入口，不把已删除项目挤进设置主页。

### 垃圾桶

显示名称、类型、删除时间和恢复操作。每行不增加卡片背景。
“清空”在标题区，只在有内容时可用；清空必须二次确认并明确无法恢复。
恢复后条目轻柔消失，底部提示“已恢复至今日 / 计划 / 目标”，具体位置遵循现有数据逻辑。
空态只有“垃圾桶是空的”，不放大幅插画。

### 确认与反馈

任务、子任务、计划、目标的删除都保留确认。明确列出要删除的内容，并正确说明恢复方式。
清空垃圾桶和迁移后删除原数据需使用各自准确文案，不能复用“可在垃圾桶恢复”。
恢复操作无需弹窗。保存状态尽量安静，可在失败时显示重试提示；不得先显示“已保存”再实际落盘。

## 交互原型

| 触发 | 结果 | 过渡 |
| --- | --- | --- |
| 悬停一行 | 底色轻微变化，出现操作提示 | 100–120ms 淡入 |
| 点击任务文字区域 | 原位展开；其他打开项先完成保存 | 180ms 高度与透明度变化 |
| 点击主 / 子完成圈 | 只改变对应完成状态，不误展开 | 120ms 勾选反馈 |
| 点击添加整行 | 就地变成输入区，自动聚焦 | 120ms |
| 新任务输入后 Enter / 点击外部 | 非空内容创建；全空白取消并回到 + | 保持添加行紧随列表 |
| 新计划点击外部 | 名称和日期有效才创建；缺少日期保留并提示 | 字段级提示 |
| 已有内容点击空白 / Esc | 有效修改提交后收起；未完成的输入法组合不提交 | 180ms |
| 输入现有标题为空 | 显示必要校验，不覆盖已有有效标题 | 无模态弹窗 |
| 日历 / 颜色选择 | 视为当前编辑区的一部分，不能误触外部保存 | 120ms |
| 切换视图 | 完成有效编辑，切换到目标视图并保留各自滚动位置 | 140–160ms 淡入 |
| 点击删除 | 居中小确认框，焦点先落在“取消” | 120ms |
| 点击关闭 | 隐藏到托盘，保留窗口状态 | 系统行为 |
| 托盘左键 / 显示 | 恢复窗口并聚焦，维持先前页面 | 系统行为 |
| 托盘打开设置 | 显示窗口并进入已有设置页，避免重复叠页 | 160ms |
| 开启减少动态效果 | 去掉高度运动，仅短淡入或直接切换 | 0–80ms |

点击窗口标题栏空白处可拖动，设置、关闭等按钮区域不参与拖动。
键盘 Tab 可以遍历可操作项；焦点描边需看得见。所有图标有提示文字。
数据保存完成前不删除编辑状态；保存失败保留输入以便重试。
不使用弹跳、夸张滑动、庆祝动效或每次保存弹出通知。

## Figma 建议文件结构

1. Foundations：颜色、文字、间距、图标、真实 Logo。
2. Components：WindowBar、ViewHeader、TaskRow、SubtaskRow、PlanRow、GoalRow、AddRow、SettingsRow、TrashRow、ConfirmDialog。
3. Screens：按 01–09 重建对应画面。
4. States：空列表、添加中、输入无效、保存失败、完成、逾期、垃圾桶为空、字体列表、目标选择器、迁移确认、托盘菜单。
5. Prototype：建立今日 → 展开任务 → 新增子任务 → 收起，以及计划 → 改日期、删除 → 恢复的完整路径。

组件使用 Auto Layout 和 Variants。列表高度跟随内容，窗口标题栏固定，正文区域滚动。先做 400px，再验证 340px 和长中文标题。
图片作为视觉参考放在单独页面锁定；不要将整张图片当作可交互组件。

## 生图与最终设计的差异

- 生成图局部出现的小圆角需要改成 0。
- 生图里的蓝色 / 黄色样本略鲜艳，实际使用更低饱和度的目标颜色。
- 第一张稿的计划行缺少完成圈，需补齐。
- 第三张稿“关闭窗口”旁箭头应去掉；今日背景不应有返回箭头。
- 部分长文案、微小文字和日历可能有生图误差，重建时按真实数据排版。
- 生成图里的任务箭头多为常显，最终仅悬停 / 焦点时强调；点击区域始终是整行。
- 按比例重建到 400 × 720，不以生成图中的像素距离作为精确规格。
